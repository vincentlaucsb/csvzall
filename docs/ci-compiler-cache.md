# CI compiler caching and build limits

Native PR and default-branch CI use ccache on Linux/macOS and sccache on Windows.
Windows uses Ninja with MSVC because CMake compiler launchers work with Ninja
and Makefile generators. The dedicated viewer asset workflow continues checking
the native default generators, including Visual Studio.

Native builds run at most two compile jobs on macOS and four on Linux/Windows.
Coverage retains its two-job limit. This avoids launching all translation units
at once on the macOS ARM runner's limited memory. All existing tests still run.

The shared `.github/actions/compiler-cache` action persists only compiler-cache
data, with a 500 MB size limit per configuration. Keys separate OS, architecture,
toolchain/generator, native compression variants, and coverage instrumentation.
Each run attempt saves a fresh snapshot and restores the most recent compatible
one. Default-branch runs seed caches that new PRs can read; PR-created caches are
scoped to that PR by GitHub. The compiler cache itself validates source/header
content and compiler options; no relaxed timestamp or header checks are enabled.

Build trees and test outputs are not restored by this action. Coverage `.gcno`
compile metadata can be reused with its object, but `.gcda` execution counters
and coverage reports are generated by the current run. Paths remain stable on
GitHub runners; no coverage path checks are disabled. Existing FetchContent
caching remains separate.

Release workflows do not use the compiler-cache action or compiler launchers.
They retain their existing FetchContent dependency cache. WASM CI is unchanged.

To measure the change, compare the first PR run with a rerun of the same commit
on fresh runners. Record build-step and total-job durations and compiler cache
hit/miss statistics. Both runs must execute all tests; compare coverage XML to
ensure reused compile metadata still produces the same coverage. A later source
edit should miss for affected translation units while reusing unchanged ones.
Separate first-run installation/cache-transfer overhead from compilation savings.
